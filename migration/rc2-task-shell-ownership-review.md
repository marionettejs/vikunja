# Bounded Task/record/shell ownership review

Reviewed root `cb3b2c23d` lineage after results/Gantt/BubbleMenu fixes. Source-based review only: no browser/backend/build/tests/source mutation. No additional supported defect was proven, so no patch is proposed.

TaskApplication `features/task/application.ts:51–64` passes the Application start signal into the task read and checks cancellation before/after starting actions. It creates a TaskRecordSession for standalone detail or borrows the ProjectApplication Gantt record. `:90–97` closes only an owned record on stop and clears its reference; borrowed records remain owned by ProjectApplication, whose cancelSurfaceWrites closes/clears Gantt records. Closing a borrowed record merely because the modal disappears would break still-live Gantt ownership.

TaskRecordSession `task-record.ts:19–45` checks both record life and caller before each queued transport, merges life/caller cancellation into request, and checks request after completion before record/listener publication. It also preserves relation publications during whole-task writes. close aborts life and clears listeners/flushers. Existing record tests cover active/queued cancellation, ignored-abort transport, serialization, rejected writes, concurrent relations and detached snapshots.

Detail Views supply caller cancellation: heading/basic fields abort their request on destroy; description life reaches record.save and is aborted on destroy; color/move/reminders/repeat and attachments supply their own life signal. TaskDetail beforeDestroy releases record observer, project observer, description flusher and scrolling observers. TaskActionsApplication combines workflow/caller/confirmation lifetimes, checks after flush and transport, and only the same current lifecycle can clear busy. Existing workflow tests cover stop/restart with held duplicate and late navigation.

Shell and route authority: root Application `app/application.ts:60–79` synchronously stops Workspace on signed-out/identity-changing before routing, and commitNavigation increments navigation before awaiting description flush and checks it after await. Workspace onBeforeStop stops current destination and increments routeRevision; Shell owns its chrome feature Applications/NavigationView. Navigation project/favorite writes check life after transport; onBeforeDestroy aborts it and removes drag/resize listeners. Width queue captures its initiating user, but supported signed-out/identity-changing destroys the navigation owner and aborts its life before continuation. A test that swaps Session data while intentionally retaining NavigationView would not prove a supported root lifecycle failure.

ProjectBackground clear/destroy aborts its current request, revokes owned URLs; post-fetch callback checks cancellation/destroy and revokes a newly returned URL. Profile-changed chrome publication is gated by Shell.isRunning.

Limits: TaskApplication has no independent root-view beforeDestroy stop hook. In the inspected supported paths, Workspace stops the app and each detail child cancels its own operations; merely observing an app retaining an unused record after artificial detached-region teardown is not enough to justify another stop hook. Workspace.closeTask checks isRunning after flush, while root commitNavigation owns navigation revision; source alone does not establish a stale-close race under actual root dispatch. Any further change here should require a real root/Workspace navigation reproduction instead of a mocked ownership graph or generic framework.
